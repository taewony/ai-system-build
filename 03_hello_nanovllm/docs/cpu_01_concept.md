# CPU01. vLLM의 두뇌와 근육 분리하기

vLLM을 공부할 때 가장 큰 장벽은 **"GPU가 없으면 아예 코드가 안 돌아간다"**는 점입니다. 하지만 vLLM의 진짜 혁신은 GPU 연산 코드(CUDA/Triton)에만 있는 것이 아닙니다. 

진짜 핵심은 **"데이터를 어디에 넣을지 결정하고(Memory Manager)"**, **"누구를 먼저 처리할지 정하는(Scheduler)"** **CPU 로직**에 있습니다.

---

## 1. Control Plane vs Data Plane

vLLM의 아키텍처는 크게 두 부분으로 나뉩니다.

*   **Control Plane (두뇌, CPU)**: `LLMEngine`, `Scheduler`, `BlockManager`, `Sequence`
    - "이 요청은 지금 메모리가 부족하니 잠시 멈춰(Preemption)!"
    - "이 단어들은 10번 블록에 넣어둬(PagedAttention Mapping)!"
    - **핵심 기술**: 복잡한 비즈니스 로직, 상태 관리, 알고리즘.
    - **실행 환경**: **CPU (Python)**

*   **Data Plane (근육, GPU)**: `Attention`, `Linear`, `FlashAttn`, `Triton Kernel`
    - "나는 입력된 숫자를 행렬 연산해서 다음 단어의 확률값만 구해."
    - "메모리 주소는 CPU가 알려준 대로만 쓸게."
    - **핵심 기술**: 하드웨어 최적화, 대규모 병렬 연산.
    - **실행 환경**: **GPU (CUDA/C++/Triton)**

## 2. 왜 CPU 시뮬레이션인가?

우리가 `nano-vllm`을 CPU 모드에서 공부해야 하는 이유는 명확합니다.

1.  **논리에 집중**: 복잡한 GPU 라이브러리 설치(NVIDIA Driver, CUDA 등) 없이, 알고리즘의 본질을 파악할 수 있습니다.
2.  **디버깅 용이성**: `print()` 문이나 디버거(PDB)를 사용하여 메모리 블록이 어떻게 쪼개지고 합쳐지는지 실시간으로 관찰할 수 있습니다.
3.  **제한 없는 실험**: GPU 메모리 한계에 구애받지 않고, 10,000명의 가상 사용자를 동시에 시뮬레이션하며 스케줄러의 한계를 테스트할 수 있습니다.

## 📝 학생들을 위한 요약
*   vLLM은 단순히 '빠른 연산'만 하는 도구가 아니라, **'똑똑한 메모리 관리자'**입니다.
*   똑똑한 관리자(CPU)의 논리는 GPU 없이도 완벽하게 이해하고 실험할 수 있습니다.
*   우리는 이제 GPU(근육)를 가짜로 대체하고, vLLM의 진정한 핵심인 **제어 논리(두뇌)**를 파헤쳐 볼 것입니다.
