생성된 텍스트 (Generated)

1 Pre-fill (프리필) 단계

사용자가 입력한 프롬프트 전체를 한꺼번에 읽어 들이는 과정입니다.

  • 병렬 처리: 모든 단어를 동시에 계산하여 GPU 연산력(Compute)을 100% 활용합니다.
  • KV 캐시 생성: 연산 결과인 Key와 Value 텐서를 KV Cache 메모리에 한 번에 저장합니다.

2 Decode (디코드) 단계

LLM이 다음 단어를 하나씩 순차적으로 만들어내는 과정입니다.

  • 순차적 병목: 이전 단어가 생성되어야 다음 단어를 만들 수 있습니다.
  • 메모리 대역폭 중요: 연산량은 적지만 매번 메모리(KV 캐시)를 읽어야 해서 메모리 속도가 가장 중요합니다.

💡 vLLM의 핵심 혁신

PagedAttention 이란?

일반적인 엔진은 단어가 얼마나 생성될지 몰라 KV 캐시 메모리를 통째로(크게) 미리 할당하여 메모리 낭비(단편화)가 심했습니다.

vLLM은 OS의 가상 메모리처럼 KV 캐시를 작은 '블록(Page)' 단위로 쪼개어 필요할 때마다 동적으로 할당합니다. 이로 인해 메모리 낭비를 없애고, 한 번에 더 많은 사용자의 요청(Batch)을 처리해 속도를 극대화합니다!
