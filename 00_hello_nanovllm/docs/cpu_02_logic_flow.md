# CPU02. 가짜 근육(Mock)과 실제 두뇌(Control)

vLLM의 **제어 로직(Control Logic)**은 GPU에서 연산이 실제로 일어났는지, 아니면 우리가 가짜로 계산한 척만 하는지 모릅니다. 

단지 **"단어(Token)가 하나 생성되었어"**라는 정보와 **"연산 시간이 이만큼 걸렸어"**라는 사실만 받으면 됩니다.

---

## 1. Mocking: GPU 연산의 흉내내기

`src/cpu_sim/mock_model_runner.py`에서 우리가 만든 가짜 근육은 어떻게 동작할까요?

```python
def run(self, seqs, is_prefill):
    # 1. GPU에서 돌아가는 척 잠시 '대기' (연산 시간 시뮬레이션)
    time.sleep(0.005) 

    # 2. 실제 행렬 연산 대신 '가짜 단어'를 반환
    token_ids = [random.randint(0, vocab_size) for _ in seqs]
    return token_ids
```

### 왜 이렇게 해도 되나요?
- **vLLM의 관심사**: "이 단어가 '사과'인지 '포도'인지"는 상관하지 않습니다.
- **진짜 관심사**: "단어가 하나 생성되었으니, **메모리 블록(Block)**에 빈자리가 있는지 확인해!" (BlockManager)
- **진짜 관심사**: "단어가 계속 생성되어 최대 길이에 도달했으면 **메모리를 회수(Deallocate)**해!" (Scheduler)

## 2. GPU 모방 인터페이스(Mocked Interface) 상세

시뮬레이션 모드에서 GPU의 복잡한 연산을 대신하는 핵심 인터페이스 리스트입니다. 이 함수들은 실제로는 수십억 개의 파라미터를 계산하지만, 우리 버전에서는 논리 흐름을 위해 가짜 데이터를 즉시 반환합니다.

| 기능명 (Method) | 역할 (Responsibility) | 입력 (Input) | 출력 (Output) |
| :--- | :--- | :--- | :--- |
| **`run`** | **핵심 추론 엔진**<br>입력된 문장들을 보고 다음 단어 하나를 생성합니다. | `seqs`: 현재 실행 중인 Sequence 객체 리스트<br>`is_prefill`: 최초 입력 처리 여부 (True/False) | `token_ids`: 각 Sequence마다 생성된 **다음 토큰 ID 리스트** (List[int]) |
| **`call`** | **명령 전달자**<br>엔진(CPU)이 모델(GPU)에게 특정 작업(run, exit 등)을 시킵니다. | `method`: 실행할 기능 이름 (str)<br>`*args`: 해당 기능에 필요한 인자들 | 각 메서드 실행 결과값 (주로 `token_ids` 또는 `None`) |
| **`exit`** | **자원 정리**<br>GPU 메모리를 해제하고 프로세스를 안전하게 종료합니다. | 없음 | 없음 (`None`) |

### 상세 동작 원리:
1.  **`run(seqs, is_prefill=True)` (Prefill 단계)**:
    - **입력**: 사용자가 보낸 질문(Prompt) 전체가 전달됩니다.
    - **가짜 동작**: 질문의 길이에 비례하여 아주 짧은 시간(`time.sleep`) 동안 대기합니다.
    - **출력**: 질문 바로 다음에 올 첫 번째 단어 ID를 생성합니다.

2.  **`run(seqs, is_prefill=False)` (Decode 단계)**:
    - **입력**: 현재 생성 중인 문장들이 전달됩니다.
    - **가짜 동작**: 매우 빠르게(0.005초) 단어 하나를 생성하는 척합니다.
    - **출력**: 각 문장 뒤에 붙을 새로운 단어 ID를 하나씩 반환합니다.

## 3. 두뇌(Control Logic)의 역할

GPU가 가짜 토큰을 던져주면, CPU에 있는 vLLM의 두뇌는 바빠집니다.

1.  **BlockManager**: "가짜 토큰이 하나 추가되었으니, 현재 블록이 꽉 찼나? 찼다면 다음 빈 물리 블록을 연결해 줘."
2.  **Scheduler**: "지금 실행 중인 모든 요청에 단어가 하나씩 늘었어. GPU 메모리가 부족해지기 시작했으니, 제일 오래된 요청 하나를 잠시 멈춰(Preempt)!"
3.  **Sequence**: "내 문장 리스트에 가짜 토큰 ID를 추가하고, 답변 길이를 업데이트하자."

## 📝 학생들을 위한 요약
*   **분리 설계**: vLLM은 연산(What to calculate)과 관리(How to manage)가 명확히 분리된 설계입니다.
*   **가상 실험**: 가짜 연산자를 사용하면, 실제 GPU가 없어도 **메모리 부족 상황(OOM)**이나 **스케줄링 병목 현상**을 완벽하게 재현하고 관찰할 수 있습니다.
*   **본질의 이해**: 연산은 하드웨어가 하지만, **관리 논리(PagedAttention, Scheduling)**는 개발자가 짭니다. 우리는 지금 그 '관리 논리'를 배우고 있는 것입니다.
