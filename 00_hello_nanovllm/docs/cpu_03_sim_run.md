# CPU03. 시뮬레이션 실행과 관찰

우리가 만든 **가짜 근육(MockModelRunner)**을 장착하고, vLLM의 **진짜 두뇌(Scheduler, BlockManager)**를 가동해 봅시다. 이 과정을 통해 vLLM 내부에서 어떤 일이 벌어지는지 생생하게 볼 수 있습니다.

---

## 1. 시뮬레이션 코드 실행 (`src/cpu_sim/run_cpu_sim.py`)

다음 명령어를 통해 GPU가 없는 환경(PC/노트북)에서 시뮬레이션을 시작합니다.

```bash
python src/cpu_sim/run_cpu_sim.py
```

## 2. 우리가 관찰할 핵심 포인트

시뮬레이션이 돌아가면서 출력하는 로그를 보고 다음을 찾아보세요.

### 🔍 포인트 A: Prefill (마중물 단계)
- 처음 질문이 들어왔을 때, 질문의 길이만큼 **메모리 블록(Block)**이 한꺼번에 할당되는지 보세요.
- `BlockManager`가 비어있는 블록 목록(`free_block_ids`)에서 몇 개를 꺼내 쓰는지 확인하세요.

### 🔍 포인트 B: Decode (한 단어씩 생성)
- 질문 처리가 끝나고 단어가 하나씩 늘어날 때, `Slot Mapping`이 어떻게 변하는지 관찰하세요.
- 특정 순간에 블록이 꽉 차면, 새로운 물리 블록이 추가로 할당되는 소리를 들어보세요(로그로 확인).

### 🔍 포인트 C: Finishing (메모리 반납)
- 요청된 단어 생성이 완료되면, `BlockManager`가 해당 블록들을 다시 `free_block_ids`로 깨끗하게 돌려주는지(Deallocate) 확인하세요.

## 📝 학생들을 위한 요약
- **눈으로 보는 vLLM**: 이제 vLLM은 더 이상 신비로운 블랙박스가 아닙니다.
- **논리 검증**: 우리가 공부한 `PagedAttention`과 `Scheduler` 알고리즘이 실제로 CPU에서 어떻게 동작하는지 증명되었습니다.
- **응용 가능성**: 이 시뮬레이터에서 스케줄링 정책을 바꿔보거나(예: FIFO -> Priority), 메모리 블록 크기를 조절하며 최적의 성능을 찾아보는 실험도 가능합니다.

이제 여러분은 **vLLM의 설계 철학을 꿰뚫어 보는 진짜 엔지니어**가 되었습니다!
